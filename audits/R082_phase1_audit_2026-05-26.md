### Why

- Line 761: `best_state = None`

Only `src/train_v11_mulminet_softf1.py` calls `torch.save` (R-031 SoftF1 fine-tune
artifact). The base V11/V11plus/V11_aug trainer never persists checkpoints.

## 2. Extraction contract (defined for future Phase 2)

If/when V11 is retrained with checkpoint save enabled, the OOF-safe extraction
contract is:

### Architectural insertion point
V11's forward pass (`src/train_v11_transformer.py` lines 397–411):

```python
last_idx_expanded = last_idx.view(B, 1, 1).expand(B, 1, self.d_model)
last_repr = x.gather(1, last_idx_expanded).squeeze(1)    # (B, 192)  ← extract this
# action_head(last_repr), point_head(last_repr) ← heads use this

real_mask = (~pad_mask).float().unsqueeze(-1)
pool_repr = (x * real_mask).sum(dim=1) / real_mask.sum(dim=1).clamp(min=1)  # (B, 192) ← extract this
# server_head(pool_repr) ← head uses this
```

Two 192-d embeddings per row:
- `last_repr` — input to action + point heads
- `pool_repr` — input to server head

### OOF-safe protocol
- **Validation embeddings**: per training fold `f`, only model `f` (which did NOT
  train on fold-`f` val rows) computes embeddings for those val rows. This is
  identical to how the existing V11 OOF arrays are constructed; safety follows
  from the existing GroupKFold(by match) split.
- **Test embeddings**: every fold model computes embeddings on the full test
  set; average across 5 folds (parallel to how test prediction averaging works
  in V11's `test_act_acc += at / len(splits)` pattern).

### Required trainer changes (V11)
1. Add `--save-checkpoint` CLI flag.
2. After `model.load_state_dict({k: v.to(DEVICE) ...})` on line 807, add:
   ```python
   if args.save_checkpoint:
       os.makedirs("models", exist_ok=True)
       torch.save({"state_dict": {k: v.cpu() for k, v in model.state_dict().items()},
                   "fold": fold, "arch_config": {...}},
                  f"models/v11_fold{fold}.pt")
   ```
3. Add `extract_embeddings: bool = False` arg to `RallyTransformer.forward`;
   when True, return `(action_logits, point_logits, server_logit, last_repr, pool_repr)`.
4. Add a separate `src/extract_v11_embeddings.py` script that:
   - Loads each fold checkpoint
   - Runs inference on that fold's val rows → saves `oof_predictions/v11_emb_last_oof.npy` (69712 × 192)
   - Runs inference on test → averages across 5 folds → `oof_predictions/v11_emb_last_test.npy` (1845 × 192)
   - Same for `pool_repr` → `v11_emb_pool_*` arrays.

### Leakage checks (must verify before extraction)
- ❌ No `gamePlayerId` / `gamePlayerOtherId` in the embedding features ← V11's
  internal `player_emb` IS used to compute the embedding (architectural;
  cannot remove). Question: does this constitute "raw player ID leakage"?
  **Codex review needed before Phase 2**.
- ❌ No `rally_uid` ordering inference ← V11 takes rally context as a sequence
  but does NOT use rally_uid as a feature. Safe.
- ❌ No test SGP truth ← V11's server head trains on train SGP only. Safe.
- ✅ Val embeddings strictly come from non-trained fold model ← protocol above.
